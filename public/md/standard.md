# 代码巡检
---------------------------------------------------------------------

帮助开发者养成在具体需求中渐进式落地规范的好习惯，让代码规范，工程规范更好的落地，提升代码质量

质量分采用阶梯分制度，即通过叠加总分来构成分值体系，主要优点：

（1）新增治理维度不影响现有维度分值评估体系

（2）新增治理指标不会导致分值塌陷问题，有利于持续治理

（3）优化可理解为不断提升相关维度分值的过程

（4）分值占比均衡性由治理目标决定，自由度高

## 指标详解
（1）ES单文件平均缺陷数（16分）
- `计算逻辑`：根据项目的 error 和 warning 数量总数除以扫描总数，即单文件的平均JS违规错误和警告数，加以权重计算得出，具体占比 error （0.7）和 warning（0.3），超过一定阈值得 0 分，简言之，单文件平均错误和告警数越低，得分越高，无错误和告警时即得满分，最低分为0分，不会出现负分
- `治理目的`：拉平大中小项目的考量标准，不以绝对的错误和告警数量多少来评定，而是聚焦单文件的平均错误，警告数，更加的公平，可以减少业务集中性处理错误，警告的暴力手段，更适合作为长期指标，帮助开发者渐进式的落实基础规范，深刻体验量变到质变的收敛过程，帮助开发者养成在具体需求中渐进式落地规范的好习惯，让研发规范更好的落地

（2）ES缺陷波及检测（4分）
- `计算逻辑`：有错误或者警告的文件数占总扫描文件数的比例，比例越低得分越高，占比为0时，得满分，最低分为0分，不会出现负分
- `治理目的`：鼓励在收敛规范过程中优先处理单个文件的所有告警，错误，反映在日常开发，有利于拆分具体的优化策略到具体的需求中去，帮助开发者养成在具体需求中渐进式落地规范的好习惯

（3）CSS单文件平均缺陷数（4分）
- `计算逻辑`：同ES代码规范合规
- `治理目的`：同ES代码规范合规

（4）CSS缺陷波及检测（2分）
